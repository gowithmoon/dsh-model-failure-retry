# 切换模型通过"改会话模型 + 结束本轮 + 自动续轮"实现

DSH 的 `agent/request-error` 重试复用本步已固定的模型选择，无法在本次请求内换模型。我们选择调用 `agent.model.select()` 切到候选模型、结束本轮，再用 `agent.followup()` 自动续一轮；而不是在 `llm/stream` 里替换流，因为后者绕过调用准备与计费统计，随 DSH 升级容易失效。代价是会话里会出现一个续轮断点。

续轮消息必须带一句非空的简短指令（续轮指令），来源用插件自己的 `kind`、`form: 'notice'` 并给出一行 `summary`。不能发空消息：空文本块会原样进入请求，Anthropic 等提供方会拒绝。

## 原型结论（#2，DSH 0.2.2-rc.1，headless + mock 提供方）

- 时序：在 `agent/request-error` 里 `select()` 后返回 `undefined`，本轮以 `turn/end {kind:"error", code:"RATE_LIMIT"}` 结束；在 `agent/status` 变为 `idle` 时调 `followup()`，下一轮自动在新模型上开始并完成。
- 模型可见内容：续轮消息之后，DSH 自己会插入 `[model changed: assistant turns above this point were generated by X; the session continues with Y]`。所以续轮指令只需说明"上一个模型失败，接着做"，不用重复切换细节。
- 工具调用中途失败：已执行的 `assistant tool_calls` + `tool` 结果完整保留，新模型能接着往下走。
- 会话记录：续轮消息以 `user/message` 落盘；Web 聊天视图把非 `user` 来源的消息渲染为可折叠的上下文行（按源码推断，未在真实 GUI 里看过）。
- 遗留：会话标题生成等旁路请求不走 `agent/request-error`，仍会打到失败的模型上，不归本插件处理。
